# Bastion Mailer

**Status**: Plan | **Library**: `bastion_mailer` (separate repo) | **Part of**: [Bastion Design Spec](README.md)

---

## Overview

`bastion_mailer` is a standalone email library for Bastion applications — the same relationship Depot has to Bastion. It provides:

- A composable `Email` builder type
- An `Adapter` interface so you can swap delivery backends (SMTP, SendGrid, Mailgun, SES, test)
- Template integration: render `.march.html` email templates to HTML + text
- `deliver/2` (synchronous) and `deliver_later/2` (async via Vault task queue)
- A test adapter with assertion helpers
- A dev preview UI at `/_bastion/mail` showing captured emails

## Types

```march
type Address = Address(String, String)  -- (display_name, email_address)

type Email = Email({
  from        : Address,
  to          : List(Address),
  cc          : List(Address),
  bcc         : List(Address),
  reply_to    : Option(Address),
  subject     : String,

```

### `Bastion.Mailer.Attachment`

```march
type Attachment = Attachment({
  filename     : String,
  content_type : String,
  data         : Bytes,
  disposition  : AttachmentDisposition,
})

type AttachmentDisposition =
    Inline(String)   -- content-id for inline images
  | Attachment
```

### `Bastion.Mailer.Error`

```march
type MailerError =
    ConnectionFailed(String)
  | AuthFailed(String)
  | InvalidRecipient(String)
  | RateLimited(Int)          -- retry-after seconds
  | ProviderError(Int, String) -- HTTP status + body
  | Unknown(String)
```

Usage:


## Adapter Interface

```march
-- lib/adapter.march
interface MailerAdapter do
  fn deliver(email : Email, config : Map(String, String))
    : Result(String, MailerError)
end
```

Every adapter implements this. The `config` map is populated from `forge.toml` (see below).

## Public API (`Bastion.Mailer`)

```march
-- Synchronous: block until delivered or error.
fn deliver(mailer_mod, email : Email) : Result(String, MailerError)

-- Fire-and-forget: enqueue in Vault task queue, return immediately.
fn deliver_later(mailer_mod, email : Email) : Ok(())

-- Retry delivery (used by the task queue worker).
fn deliver_with_retry(mailer_mod, email : Email, attempts : Int)
  : Result(String, MailerError)
```

### App-side Mailer module

Generated by `forge bastion.gen.mailer` (or written by hand):

```march
mod MyApp.Mailer do
  use Bastion.Mailer,
    adapter: Bastion.Mailer.SMTP,
    from:    ("My App", "no-reply@myapp.com")
end
```

Calling `MyApp.Mailer.deliver(email)` dispatches through the configured adapter.

## Adapters

### SMTP (`Bastion.Mailer.SMTP`)

Uses `Net.tcp_connect` + STARTTLS. Supports:
- `host`, `port` (default 587)
- `username`, `password`
- `tls`: `"starttls"` | `"always"` | `"never"`
- `auth`: `"plain"` | `"login"` | `"none"`

### SendGrid (`Bastion.Mailer.SendGrid`)

HTTP to `https://api.sendgrid.com/v3/mail/send` with `Authorization: Bearer <api_key>`.

### Mailgun (`Bastion.Mailer.Mailgun`)

HTTP to `https://api.mailgun.net/v3/<domain>/messages` with HTTP Basic auth.

### SES (`Bastion.Mailer.SES`)

HTTP to the AWS SES API endpoint with AWS SigV4 signing.
Config: `region`, `access_key_id`, `secret_access_key` (or ambient IAM role).

### Test (`Bastion.Mailer.Test`)

Stores delivered emails in Vault under `"_bastion_mailer_test"`. Never sends actual email.

```march
-- Assertion helpers (import in test files)
fn assert_email_delivered_to(addr : String)
fn assert_email_subject(subj : String)
fn assert_email_count(n : Int)
fn refute_email_delivered()
fn delivered_emails() : List(Email)
fn clear()
```

## Template Integration

Email templates are `.march.html` files using the same `~H` lowering as web templates, but rendered to a plain `String` rather than a live response:

```
lib/emails/
├── welcome_email.march.html
├── password_reset_email.march.html
└── confirmation_email.march.html
```

```html
<!-- lib/emails/welcome_email.march.html -->
---
fn html(user, confirm_url : String) : String
---
<!DOCTYPE html>
<html>
  <body>
    <h1>Welcome, {user.name}!</h1>
    <p>Please confirm your email:</p>
    <a href="{confirm_url}">Confirm my email</a>
  </body>
</html>
```

Usage:

```march
Email.new()
|> Email.html_body(WelcomeEmail.html(user, confirm_url))
|> Email.text_body("Welcome, " ++ user.name ++ "! Confirm: " ++ confirm_url)
```

`Bastion.Mailer.Template.to_text/1` can strip HTML tags from an HTML body to auto-generate a text version if no explicit text template is provided.

## Configuration (`forge.toml`)

```toml
[deps]
bastion_mailer = { path = "/Users/80197052/code/bastion_mailer" }

[mailer]
adapter     = "smtp"       # smtp | sendgrid | mailgun | ses | test
from_name   = "My App"
from_email  = "no-reply@myapp.com"

[mailer.smtp]
host     = "smtp.postmarkapp.com"
port     = 587
username = "${SMTP_USER}"       # env var expansion at runtime
password = "${SMTP_PASS}"
tls      = "starttls"

[mailer.sendgrid]
api_key  = "${SENDGRID_API_KEY}"

[mailer.mailgun]
domain   = "mg.myapp.com"
api_key  = "${MAILGUN_API_KEY}"
region   = "us"                  # us | eu

[mailer.ses]
region            = "us-east-1"
access_key_id     = "${AWS_ACCESS_KEY_ID}"
secret_access_key = "${AWS_SECRET_ACCESS_KEY}"
```

In test environment, `adapter = "test"` is set automatically.

## Dev Preview UI

When `MARCH_ENV=dev`, the `Bastion.Mailer.Preview` plug registers `/_bastion/mail`:

- Lists all emails captured by the test adapter during the current server session
- Renders each as HTML (preview) or plain text
- Shows envelope info: from, to, cc, subject, sent-at timestamp
- Toggle between HTML and text views
- "Send to myself" button (re-delivers via the real adapter if configured)
- Integrates into the existing `/_bastion` dev dashboard

## Async Delivery (`deliver_later`)

`deliver_later/2` enqueues the email in a Vault-backed task queue using the same pattern as `Bastion.Health`'s drain mechanism:

1. Serialise the `Email` struct to JSON and `Vault.put` it under `"_bastion_mailer_queue:<uuid>"`
2. A background actor (started by `Bastion.Mailer.start_worker/1`) polls the queue and calls `deliver/2` for each entry
3. On failure: exponential back-off up to 5 attempts, then moves to `"_bastion_mailer_dead:<uuid>"`
4. Dead-letter entries visible at `/_bastion/mail/dead` in dev

**Note**: this is in-memory only. For durable async delivery across restarts, use Depot-backed queues (post-v1) or an external queue (SQS, Redis Streams).

## Build Order

1. `lib/mailer_error.march` — error types
2. `lib/email.march` + `lib/attachment.march` — pure data types
3. `lib/adapter.march` — interface declaration
4. `lib/adapters/test.march` — Vault-backed; unblocks all tests
5. `lib/adapters/smtp.march` — TCP delivery
6. `lib/template.march` — wraps lower.march rendering + `to_text/1` stripper
7. `lib/mailer.march` — dispatch + retry + `deliver_later` queue
8. `lib/adapters/sendgrid.march`, `mailgun.march`, `ses.march` — HTTP adapters
9. `lib/preview.march` — dev UI (plugs into `Bastion.Dev`)
10. `lib/forge/gen_mailer.march` — generator

## Open Questions

- **Text auto-generation**: Should `Template.to_text/1` (HTML-strip) be on by default when no explicit text body is set, or should missing text body be an error?
- **Attachments from disk vs memory**: Accept a file path (lazy read on deliver) or always pre-load bytes into the `Attachment` struct?
- **Multi-tenant from addresses**: Should the `from` be set per-email (current design) or per-mailer-module (simpler for single-tenant apps)?
